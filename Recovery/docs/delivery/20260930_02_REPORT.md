## 5. 单一干预与后缀重放

Observation：同一个完整 JSON 在 `_finalize_video_clip_qa_answer` 已为 `model_json`，却被最后一行 prose 标点检测重新标记为 truncated。工具 warning → error 后 `concrete_evidence_success=false`，跳过 Observer evidence。

Hypothesis：仅在非 `model_json` 输出应用 prose 截断检测，就能让相同内容进入 Observer → ledger；能否继续 Finish 由下游真实执行决定。

Single Intervention：B 等价于将 `_run_video_clip_qa` 中条件变为：

```python
if result.get("format_status") != "model_json" and looks_like_truncated_video_clip_qa_answer(raw_answer_text):
```

实际通过 Recovery 独立 runner 的进程内 guard hook 执行；没有写入基础源码、candidate snapshot 或演化策略。A 原判断；B 只豁免已通过既有 JSON 验证的输出；invalid JSON 仍由原有路径拒绝。

Replay：恢复同一个 `turn_005.json`（prefix 4 steps，iteration=4），恢复冻结 workspace blobs 和 RNG。两臂固定同一历史 Planner 第 5 轮委派、Observer dispatch、QA raw index 1，以确保进入同一个原始结果切点；这些是共同上游 fixture，不是新生成，也不是额外干预。原始 clip metadata / tool normalization / Observer evidence / evidence merge / 后续 Planner 与 Verifier 仍运行生产路径。后续工具若被调用也真实执行。相同 snapshot_000、模型、缓存、全局轮数与恢复预算；同一进程复用模型，分离工作目录。

该切点继承了之前 approximate apples slot 和两次 recovery 的历史状态。它测试“错误是否移动”，不测试无历史债务的新整片实验；fixture 中的 counts 是历史模型输出，不是金标准。
