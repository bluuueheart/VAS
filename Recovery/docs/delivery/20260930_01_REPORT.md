## 3. 单变量协议边界实验 — VERIFIED

**Observation**：原工具提示要求 minified JSON。截断函数却对原始字符串应用散文标点判断：多词最后一行以 `}` 或代码围栏结束，会被判 truncated。

**Hypothesis**：该启发式把已经结构校验成功的 JSON 转成工具错误，导致 Observer 无法消费有效结果。

**Minimal Intervention**：仅在 `format_status != model_json` 时继续应用散文截断启发式。保留既有 JSON / nested JSON 验证；不改模型输出、问题、阈值、工具采样或任何角色。

**Expected Change**：完整 JSON被保留；真正坏 JSON仍为 error。

**Actual Result**：同一批 11 个日志原始响应，A 为现有判定，B 为上述单变量判定：A=9 error、B=2 error，恢复 7 个有效响应；2 个真实 invalid_json 均仍被拒绝。7 个误报涉及 count、order、LVBench 63、VideoMME 001-1。

**Conclusion**：已证明这一协议边界的实现缺陷及可避免的证据损失。尚未证明修复后最终答案正确、推理更快或总体收益；没有将实验条件写回核心代码。

复现命令：`PYTHONDONTWRITEBYTECODE=1 /gemini/code/bin/python3.11 /gemini/code/Recovery/check_clip_qa_protocol.py`。
材料：[clip_qa_protocol_ab.json](runs/baseline_closure_20260930/clip_qa_protocol_ab.json)、[原始响应审计](runs/baseline_closure_20260930/clip_qa_raw_format_audit.json)。这是原始响应上的确定性边界 A/B，**不是完整任务 A/B**。

## 4. order 的门禁分歧 — VERIFIED / PARTIAL

固定第 7 轮检查点、同一 query / ledger / 既有观察 / 阈值，分别提交 A/B/C/D 四个互斥排序，现有 EvidenceVerifier 全部 `can_finish=true`。实际工具结果 `3,2` 与原提交 D 的 `1->2->3->4` 不一致，因此 Reflector 指出冲突具有依据；官方 D 正确也不能使错误的观察自动变成支持 D 的证据。

生产函数 `_has_order_answer_support` 的自然语言后备匹配，以事件描述的任一 token 首次位置作为事件位置。四个事件都有 `woman`；真实 `order_2_vs_3` slot 中四个事件的最早匹配均为位置 20。非严格排序接受相同位置，所以部分关系被误当成四事件任意排列的充分支持。

证据：[order_answer_sensitivity.json](runs/baseline_closure_20260930/order_answer_sensitivity.json)、[order_token_matching.json](runs/baseline_closure_20260930/order_token_matching.json)。未修改此函数，也未将其与协议修复混为一次干预。

## 5. Mechanism 与 Research 决策

**Mechanism — PARTIAL**：当前证据指向两个阶段：观察产生/协议交付/目标提取，以及已提取证据与候选答案的语义一致性验证。协议误报是跨 4 个失败样本的共享工程问题；needle 的主要已知断点在目标事件证据获取/提取之前，order / LVBench 的断点还涉及终止支持判定。5 条终态预算耗尽是结果，不能充当统一根因。

**Research — UNKNOWN**：当前没有证据把“多个 agent 对证据充分性长期不一致”确认为可泛化研究 bottleneck。至少部分分歧可由具体实现缺陷和错误观察解释；新运行还暴露了更早的角色引用契约失败。先消除确认的协议损失并做同输入任务级比较，再判断剩余语义/时序瓶颈；不把这些工程缺陷包装为科研贡献。本阶段不恢复 Evolver，不做全 benchmark、功能扩展或 Novelty 宣称。
