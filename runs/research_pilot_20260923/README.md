# 冻结开发先导：2026-09-23

研究问题：固定当前 techplan 四角色系统、模型权重及单题推理预算，演化取证工具和调用组合能否提升未见视频的 general / fine-grained 理解表现？本轮只建立开发基线，不检验 tool-use 本身。

## 本轮实际改动

`RL/evolution/source_mutation.py` 的源码上下文曾将三个角色提示词置前，再截取六条，导致多工具编辑请求丢失 Inspect_Frame 及其执行辅助函数。现在先保留请求工具的源码，剩余槽位提供提示词。定向复现、修复后完整性和摘要检查分别见 `source_context_before.json`、`source_context_after.json`。没有修改停止规则、评分或任务关键词。

## 实验边界

- `suite.json` 预先指定六个历史失败触发样本和六个历史正确对照。它们是开发材料，不代表总体基准分布；相关视频从后续未见视频审核和最终测试排除。
- `source_manifest.json` 冻结 111 个源码、配置和入口文件。输入 UID 与视频路径核对已通过，见 `input_check.json`。
- 基线是当前系统关闭演化，使用全新结果目录；不是会议版 ReTool。保留已有输入指纹验证下的公共预处理缓存。
- 基线最多 4 小时，包含冷启动、排队和模型加载；P1 总预算 12 小时。监督进程超时终止整个工作进程组；启动标记禁止重复启动重置预算。
- 状态以 `status.json` 和 `baseline_summary.json` 为准。部分完成、基础设施失败及无收益必须分开报告；软件检查不能作为理解性能提升证据。

## 基线之后的有限决策

先读取新轨迹确认当前仍存在的瓶颈，再在同一允许编辑面验证最多三个机制正对照：时间证据覆盖、局部视觉细节保留、证据解释。三个标签目前只是待证伪假设，不是已确认因果。旧轨迹中的取帧和 Reflector 问题已有历史修复，不能直接当成当前缺陷再次修改。

每个机制必须明确：哪个可执行函数变化、实际触发证据、观察内容变化、最终答案变化、正确对照是否受损。人工正对照只用于判断可搜索空间是否存在收益，不算自动 self-evolving 的结果。自动提案最多 12 次（失败和 no-mutation 均计数）；不根据单个结果继续添加规则。若有效干预仍无收益，按协议转向研究假设；若人工有效而自动无效，定位诊断/提案模块。通过开发筛选后才进行未见视频的固定预算配对评估。
